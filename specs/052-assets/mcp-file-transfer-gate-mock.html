Annotations

Fidelity basis

  • tokens.css + app.css are inlined verbatim from src/main/resources/static/, and the shell markup is cloned from index.html. Nothing was re-skinned.
  • The Machines screen reproduces the real screenMachines() — list rows, tag filter chips, status chips.
  • The “Menu” button visible on desktop is not a mock artefact — it is what the real CSS does. .nav-toggle { display:none } (line 128) is overridden by .btn { display:inline-flex } (line 258): same specificity, later rule wins, so spec-043’s toggle never hides. Reproduced rather than fixed — fidelity over tidiness.

Invented (does not exist yet)

  • The gating notification (bottom-right). The app's real .toast is a centred, 2.6-second, non-interactive confirmation — it cannot carry a decision. This is a separate persistent stack; it never auto-dismisses.
  • Transfers nav item + pending count, and the whole #/transfers screen.
  • Package vocabulary — PENDING_APPROVAL → APPROVED → DELIVERED, plus DENIED and EXPIRED. Borrowed from the spec-004 approval states; DELIVERED/DENIED/EXPIRED are new.
  • The transfer_files MCP tool and its required reason argument, shown on the MCP surface screen.
  • Per-file sha256 shown at review time — modelled on spec-015 content-pinning, but transfers aren't wired to it today.

Stubbed / substituted

  • Monitor, Blueprints, Runs, Tokens and App key render a placeholder — real screens, deliberately left out to keep the mock on the transfer flow.
  • Machine detail, register, and the recipe/action screens are not reachable.
  • All data is fabricated and lives in memory; there is no backend. The real app.js builds DOM through an h() helper that never touches innerHTML — this mock does, which is a mock-only shortcut, not a pattern to copy.
  • Fonts are the product's own system-font stack, so nothing is substituted.

Open questions this mock takes a position on

  • Dismissing never decides. The × closes the notification and leaves the package pending — the only way to lose a request is to let it expire.
  • Nobody watching? Requests expire after 24h undecided (see the expired package) rather than waiting forever. The window is a guess.
  • A package is atomic. You approve or deny all files at once; there is no per-file exclusion. Simplest gate, but it means one bad file sinks the batch.
  • The reason is unverified. It is rendered in mono, attributed to the agent, and labelled as a claim — the model wrote it, so it can be wrong or self-serving.
